hermes-openwrt

A signed feed carrying hermes-agent and luci-app-hermes: the Hermes Agent as a native OpenWrt service. The reference device is a GL.iNet Flint 2; x86_64 and generic aarch64 are served too.

OpenWrt 25.12 and later (apk)

wget -O /etc/apk/keys/hermes-openwrt.pem \
  https://taipanbox.github.io/hermes-openwrt/hermes-openwrt.pem

echo "https://taipanbox.github.io/hermes-openwrt/25.12/$(cat /etc/apk/arch)/packages.adb" \
  >> /etc/apk/repositories.d/customfeeds.list

apk update && apk add hermes-agent luci-app-hermes

OpenWrt 24.10 (opkg)

Pick the line for your device. opkg needs the exact architecture, and opkg print-architecture lists several of which only one is right.

# GL.iNet Flint 2 and other Cortex-A53 routers
ARCH=aarch64_cortex-a53
# x86 boxes:            ARCH=x86_64
# other 64-bit ARM:     ARCH=aarch64_generic

wget -O /tmp/hermes.pub \
  https://taipanbox.github.io/hermes-openwrt/hermes-openwrt.usign.pub
opkg-key add /tmp/hermes.pub

echo "src/gz hermes https://taipanbox.github.io/hermes-openwrt/24.10/$ARCH" \
  >> /etc/opkg/customfeeds.conf

opkg update && opkg install hermes-agent luci-app-hermes

Why the two look different

They are not the same feed in two shapes. 25.12 signs every package and the index with an EC key that apk verifies; 24.10 signs only the index, with a usign Ed25519 key that opkg verifies against a fingerprint in /etc/opkg/keys. Neither key works for the other line.

Without the right key: apk drops the repository silently and the package simply does not exist, while opkg says Signature check failed and refuses. In both cases no --force and no --allow-untrusted appears anywhere above.
